# DeepShield AI — Frontend Technical Documentation

> **Audience:** senior engineers reviewing or extending this codebase without reading the source.
> **Scope:** the complete V1 frontend (static, framework-free). Backend (Flask) integration points are specified but not yet implemented.
> **Version:** 1.0.0 · **Last updated:** 2026-08-07

---

## 1. Project Overview

### Purpose

DeepShield AI is a deepfake-detection application: users upload an image or a video (or point at a direct MP4 URL), the media is analyzed by a lightweight CNN (MobileNetV3), and the app returns a verdict (*Likely Real / Likely Deepfake*), a confidence score, a risk level, and a printable analysis report.

This repository contains the **complete frontend**, shipped with a **simulated analysis engine** so that every user flow is demonstrable end-to-end with no server. The simulation is isolated behind a single interface (`DS.api.analyze`) that is contract-compatible with the future Flask backend — swapping the engine requires zero page-level changes.

Target hardware constraint (inherited from the product spec): must run smoothly on an Intel Core i3 / 8 GB RAM / CPU-only machine. This drives most architectural choices: no framework, no build step, no heavy animation, vendored assets, small payloads.

### Technologies

| Layer | Choice | Notes |
|---|---|---|
| Markup | HTML5, semantic | 10 static pages, one file per page |
| Styling | Hand-written CSS, custom properties | No preprocessor, no Tailwind/Bootstrap |
| Behavior | Vanilla ES2020 JavaScript | No framework, no bundler, no modules — plain deferred scripts |
| Icons | Lucide v1.29 (vendored UMD build) | `data-lucide` attribute API, works offline |
| Fonts | Inter, Space Grotesk, JetBrains Mono | Self-hosted **variable** woff2 files (3 files total) |
| Dev server | `serve.js` — 45-line zero-dependency Node HTTP server | `npm run dev` → `http://localhost:8000` |
| Persistence | `localStorage` + `sessionStorage` | Wrapped behind `DS.store` / `DS.session` |

### Design philosophy

- **Premium-minimal dark UI** in the Apple / Linear / Vercel idiom: one dark canvas (`#050816`), thin borders, soft shadows, generous whitespace, subtle motion. No neon, no cyberpunk, no gradient noise. A single ambient radial glow on `<body>::before` is the only decorative background.
- **Tokens-only styling.** Every color, spacing, radius, shadow, font, and easing lives in `variables.css`. Page CSS never introduces raw values outside the palette (rgba-alpha forms of palette colors are permitted for tints).
- **Exemplar-driven consistency.** `dashboard.html` is the canonical app shell. Every other app page copies its sidebar/navbar/footer markup verbatim, varying only title, active nav link, and page content. (The pages were in fact generated by parallel agents against this contract.)
- **One data contract.** A single `scan` object flows through the entire app (upload → processing → result → report) via `sessionStorage`, with completed scans archived to `localStorage`.
- **Progressive backend adoption.** The mock engine reproduces the exact response shape the Flask API will return, including progress/stage/log hooks, so the UI is already "backend-shaped".

**Why each file exists**

- `fonts.css / variables.css / base.css / components.css` are loaded **in that order on every page**; each layer depends only on the previous one. Page CSS loads last so it can specialize without `!important`.
- `utils.js → api.js → components.js → pages/<page>.js` are loaded **in that order on every page** (all `defer`). `utils.js` creates the `DS` global namespace; everything downstream attaches to it.
- One HTML + one CSS + one JS file per page keeps ownership boundaries hard (this is also what allowed parallel generation without merge conflicts).
- `serve.js`/`package.json` exist because the machine has Node but not Python; `npm run dev` is the expected developer entry point. The site also works over `file://`.

## 4. Page Architecture

Two page archetypes exist:

- **Standalone** (`index.html`, `login.html`) — no app shell, no auth guard, full-viewport centered layouts.
- **App-shell** (the other 8) — fixed 264 px sidebar + sticky glass navbar + footer, guarded by `DS.auth.guard()` (redirects to `login.html` when no user is stored).

### 4.1 `index.html` — Splash

- **Purpose:** brand moment + auth-aware router.
- **Components:** logo mark (inline SVG), pulse rings (pure CSS), indeterminate progress bar, badge, `.fade-up` stagger.
- **Navigation:** JS only — `location.replace()` to `dashboard.html` if `DS.auth.user()` exists, else `login.html`.
- **User flow:** auto-advance after 2400 ms (800 ms under reduced motion); any click or `Enter` skips immediately.
- **State:** reads `ds_user` only. Writes nothing.
- **Important JS (`splash.js`, ~30 lines):** idempotent `go()` guarded by a `gone` flag so timer/click/keypress can race safely; `replace()` keeps splash out of history.

### 4.2 `login.html` — Login

- **Purpose:** simulated sign-in; establishes the `ds_user` record used by guards and greetings.
- **Components:** auth card, `.input-group` fields with icons, password-visibility toggle, `.field-error` validation states, primary/ghost buttons, in-button loader.
- **Navigation:** → `dashboard.html` (submit after 700 ms fake latency, or guest button). Already-authenticated visits redirect instantly.
- **User flow:** email + password (any credentials pass validation rules) or "Continue as guest".
- **State:** writes `ds_user` via `DS.auth.login(name, email)`. Display name is derived from the email local-part (`harsh.goswami@x.com` → "Harsh Goswami").
- **Important JS (`login.js`):** regex email validation + ≥4-char password; per-field `.invalid` classes cleared on input; both buttons disabled during the fake latency window; `DS.icons()` re-run after swapping the eye/eye-off icon.

### 4.3 `dashboard.html` — Dashboard (shell exemplar)

- **Purpose:** landing page after login; overview and jump-off point.
- **Components:** 4 × stat card, 2 × upload shortcut card, recent-scans table with empty state, AI-model spec card (`meta-list`), system card with two mock metric bars, badges.
- **Navigation:** sidebar (all app pages), "New scan" → `upload-image.html`, per-row "Report" → `report.html?id=<scanId>`.
- **State:** reads `ds_user` (greeting/avatar), `ds_history` (stats + table). Writes nothing.
- **Important JS (`dashboard.js`):** time-of-day greeting; count-up stat animation (rAF, cubic ease-out, skipped under reduced motion); `renderRecent()` builds table rows with `escapeHtml()` on file names; `startSystemMetrics()` random-walk CPU/RAM simulation every 2.2 s.

### 4.4 `upload-image.html` / `upload-video.html` — Upload

- **Purpose:** file intake, validation, preview, and scan-object creation. Both pages share `upload.css` + `upload.js`; behavior branches on `body[data-page]` via a `CONFIGS` map.
- **Components:** `.upload-area` drop zone (`role="button"`, keyboard-activatable), hidden file input, preview card (img / video element), file-meta row, simulated upload progress, primary/ghost action buttons; **video page only:** "Analyze from URL" card with validated URL field.
- **Navigation:** → `processing.html` on "Start analysis" or valid URL submit.
- **User flow:** drop/browse → validate (type + size) → preview + ~900 ms "preparing" progress → Start analysis. Invalid input → error toast + field state, stay on page.
- **State:** writes the initial scan object to `ds_scan` (sessionStorage). Reads nothing.
- **Important JS (`upload.js`, IIFE):**
  - Validation: MIME **or** extension must match (`jpg/jpeg/png/webp` ≤ 10 MB; `mp4/webm/mov` ≤ 100 MB) — extension fallback covers browsers reporting empty `file.type`; drag-and-drop bypasses the `accept` attribute, so JS is the real gate.
  - `makePreviewDataUrl()`: canvas downscale to ≤640 px wide, JPEG q0.7 — this small data URL (not the file) is what persists across pages. Video captures frame 0, then re-grabs at t=0.1 s after `seeked`. Whole routine is try/catch → `null` (tainted-canvas `file://` edge).
  - URL path: `new URL()` parse, `http(s)` protocol, `pathname.endsWith('.mp4')`; produces a scan with `source:'url'`, `fileSize:null`, `previewDataUrl:null`.

### 4.5 `processing.html` — Processing

- **Purpose:** live analysis theater; the only page that invokes the engine.
- **Components:** CSS-only scanner (conic-gradient ring, mask-clipped, + pulse), progress bar with mono % and ETA, injected stage list (pending/active/done), scrolling engine console (`role="log"`, timestamped, capped at 80 lines), cancel-confirmation modal.
- **Navigation:** success → `result.html` (`replace`, after a 900 ms success dwell); cancel-confirm → `dashboard.html`; missing scan → `dashboard.html`; engine failure → toast then `dashboard.html`.
- **User flow:** fully automatic; user can only cancel.
- **State:** reads `ds_scan`; on completion writes the **merged** scan (input + result fields) back to `ds_scan` **and** appends it to `ds_history`.
- **Important JS (`processing.js`):**
  - Stage labels come from `DS.api._stages(isVideo)` at runtime — the UI can never drift from the engine's pipeline definition.
  - Engine hooks map 1:1 to DOM: `onProgress`→bar/%, `onEta`→countdown, `onStage`→list state, `onLog`→console (built via `createTextNode`, so log text is always escaped).
  - Guards: unauthenticated → login; no scan → dashboard; `scan.completedAt` present (back-navigation) → forward to result **without re-running** (prevents duplicate history entries); `started` flag prevents double runs.

### 4.6 `result.html` — Result

- **Purpose:** verdict presentation for the scan currently in session.
- **Components:** SVG confidence ring (r=80, animated `stroke-dashoffset` over 1 s), enlarged verdict badge, risk chip, explanation sentence, media preview / dashed placeholder, file meta list, model spec card, 3 × stat card metrics, action row.
- **Navigation:** "View full report" / "Download report" → `report.html?id=<scanId>`; "Analyze another" → upload pages. Guards: no scan or no `prediction` → `dashboard.html` (`replace`).
- **State:** reads `ds_scan` + `DS.api.MODEL`. Writes nothing.
- **Important JS (`result.js`):** ring math `C = 2π·80 ≈ 502.65`; dasharray=C, dashoffset animated to `C·(1−confidence/100)` after a double-rAF style flush; count-up % respects reduced motion; risk chip class map Low/Medium/High → success/warning/danger; all injected strings escaped or `textContent`.

### 4.7 `report.html` — Report (print → PDF)

- **Purpose:** formal, printable analysis document; doubles as the "Reports" section with an empty state.
- **Components:** document card (`.report-doc`): doc header (brand + scan id), tinted verdict strip, 4 labeled sections of `meta-list` rows, generated summary paragraph, disclaimer; page-head actions (Download PDF, Back); empty state.
- **Navigation:** entered from result page, dashboard table rows (`?id=`), or sidebar "Reports".
- **User flow / scan resolution chain:** `?id=` → `DS.history.find(id)` → else session `ds_scan` (if completed) → else newest history entry → else empty state (document hidden, download disabled).
- **State:** reads `ds_history`, `ds_scan`, `ds_settings` (threshold, frame rate shown in the document), `DS.api.MODEL`. Writes nothing.
- **Important JS (`report.js`):** "Download PDF" = `document.title = "DeepShield-Report-<id>"` → `window.print()` → title restored on `afterprint` (the title becomes the suggested PDF filename). All fields set via `textContent`.
- **Print pipeline (`report.css @media print`):** hides shell/actions/toasts, removes the sidebar offset, neutralizes `.fade-up` (otherwise animated content prints invisible), forces white canvas + `#111`/`#555` ink + `#ddd` rules, converts badges to outline chips, and preserves the verdict-strip tint via scoped `print-color-adjust: exact`. `@page { margin: 16mm }`.

### 4.8 `about.html` — About

- **Purpose:** mission, how-it-works, tech stack, model card, responsible-use notes. Fully static.
- **Components:** mission card, 3 step cards (mono numerals 01–03), 4 tech cards, model `meta-list`, warning-accented use-list, version strip.
- **State / JS:** `about.js` is the auth guard only; shell behavior comes from `components.js`.

### 4.9 `settings.html` — Settings

- **Purpose:** user preferences + local-data management.
- **Components:** settings rows (label/hint left, control right), select (frame sampling 0.5/1/2 fps), range slider (threshold 50–90 %, live mono readout), 2 switches (reduced motion, auto-delete), clear-history confirm modal, system `meta-list` with "Simulated (demo)" engine badge.
- **State:** reads/writes `ds_settings` exclusively through `DS.settings.get()/set()`; `set()` also re-applies the reduced-motion flag to `<html data-reduced-motion>` immediately. Clear-history removes `ds_history`.
- **Important JS (`settings.js`):** persistence is immediate per change; only the "Settings saved" toast is debounced (400 ms) so slider drags don't spam. Modal confirm → `DS.history.clear()` → live count update → programmatic `DS.modal.close()` → success toast.

### Theme

Single dark theme. Theming hooks exist implicitly (every color is a variable), but no light theme is defined in V1.

### Typography

- Headings: Space Grotesk 600, tight tracking (−0.02 em), fluid sizes via `clamp()` (h1 = 26→34 px).
- Body: Inter 15 px / 1.6.
- **All numerals** (stats, %, ids, versions, timestamps): JetBrains Mono via `.mono`, with `font-variant-numeric: tabular-nums` for stable columns.
- Overline labels: `.eyebrow` (12 px, +0.08 em tracking, uppercase, accent color).

### Layout system

- App shell: fixed `264px` sidebar; `.app-main { margin-left: var(--sidebar-w) }`; sticky 64 px glass navbar; `.page` centered at `max-width: 1200px + padding`.
- Grids are page-scoped: dashboard `2fr 1fr`, result `1fr 1.4fr`, about steps `3 col`, tech `4 col`, upload preview `minmax(0,400px) 1fr`. All collapse per §13.
- Spacing exclusively via `--s-*`; card padding via `.card-pad` (24) / `.card-pad-lg` (32).

### Responsive system

Two global breakpoints in `components.css` (≤1024 px: off-canvas sidebar, hamburger appears, stat grid 4→2; ≤640 px: tighter paddings, stat grid →1) plus page-level queries at the same two widths. See §13.

### Animations

| Animation | Where | Mechanism |
|---|---|---|
| `.fade-up` entry (+`data-delay` 1–4 stagger) | all pages | opacity+translateY keyframe, 400 ms |
| Pulse rings | splash logo, status dots | scale+fade keyframes |
| Scanner | processing | conic-gradient ring (mask-clipped) rotating 2.4 s linear + pulse |
| Indeterminate bar | splash | translateX keyframe |
| Progress bars | everywhere | width transition 240 ms |
| Confidence ring | result | `stroke-dashoffset` transition 1 s |
| Count-ups | dashboard stats, result % | rAF cubic ease-out |
| Hover | cards lift −2 px, buttons glow, arrows slide | transform/box-shadow transitions |
| Toast in/out | global | translateX+fade keyframes |

All keyframe/transition animation is neutralized by three cooperating mechanisms: `@media (prefers-reduced-motion: reduce)`, the in-app `<html data-reduced-motion="true">` override, and JS checks before rAF count-ups.

### Utility classes (`base.css`)

`.mono`, `.text-2/.text-3`, `.text-sm/.text-xs`, `.eyebrow`, `.flex`, `.flex-col`, `.items-center`, `.justify-between`, `.gap-1/2/3`, `.container`, `.icon/.icon-sm/.icon-lg/.icon-xl`, `.fade-up[data-delay]`, and the global `[hidden] { display: none !important }` guarantee.

## 7. JavaScript Architecture

### Global namespace

Everything lives under a single global `DS` (created by `utils.js`). No modules, no bundler; load order is the dependency graph.

```
DS
├── KEYS            { USER:'ds_user', SCAN:'ds_scan', HISTORY:'ds_history', SETTINGS:'ds_settings' }
├── store / session  safe JSON wrappers over localStorage / sessionStorage (get/set/remove, try/catch)
├── util             qs, qsa, formatBytes, formatDuration, formatDate, uid('SCAN-XXXXXX'),
│                    hash (FNV-1a — seeds the mock verdict), initials, greeting
├── history          all() / add(scan) (unshift, cap 50) / find(id) / clear()
├── settings         get() (defaults ⊕ stored) / set(patch) / apply() → <html data-reduced-motion>
│                    defaults: { frameRate:1, threshold:60, reducedMotion:false, autoDelete:true }
├── auth             user() / login(name,email) / logout() / guard() → redirect login.html
├── api              MODE ('simulated'|'live'), ENDPOINT '/api/analyze', MODEL {…},
│                    analyze(scan, hooks) → Promise<result>
│                    _analyzeSimulated (120 ms tick; 5.6 s image / 8.2 s video)
│                    _analyzeLive (fetch stub for Flask)
│                    _stages(isVideo) (weighted pipeline definition)
│                    _verdictFor(scan) (deterministic seeded verdict)
├── toast(msg, type, {title, duration})
├── modal            open(id) / close(id?) / _bind() — [data-modal-open/close], Esc, overlay click
├── sidebar          _bind() — [data-sidebar-toggle], body.sidebar-open
├── shell            hydrate() — avatar initials, [data-user-name], [data-logout], [data-year]
└── icons()          lucide.createIcons — call again after any innerHTML injection of data-lucide
```

### File-by-file

| File | Role | Key details |
|---|---|---|
| `utils.js` | namespace + primitives | storage wrappers never throw (quota / file:// safe); applies persisted reduced-motion flag at parse time |
| `api.js` | engine seam | simulated verdict: filename containing `fake/synth/gen` → deepfake, `real/orig` → real, else FNV-hash seeded (42 % fake); confidence 72–97; risk derived from verdict+confidence; emits stage/log/progress/eta through hooks |
| `components.js` | shared runtime | one delegated `click` listener each for modals and sidebar (works for injected content); `DOMContentLoaded` boot: `modal._bind → sidebar._bind → shell.hydrate → icons()` |
| `pages/*.js` | controllers | each wraps everything in `DOMContentLoaded`; app pages call `DS.auth.guard()` first; upload/processing use IIFE + `'use strict'` |

### Data flow (the scan lifecycle)

```
upload.js                      processing.js                        result.js / report.js
─────────                      ─────────────                        ─────────────────────
scan = {id, fileName,          scan = session.get(ds_scan)          scan = session.get(ds_scan)
 fileType, fileSize,     ───►  DS.api.analyze(scan, hooks)    ───►  (report also: ?id= →

session.set(ds_scan)            history.add(merged)  → ds_history   render only, no writes
```

Result fields added by the engine: `prediction ('real'|'deepfake')`, `confidence (int %)`, `riskLevel ('Low'|'Medium'|'High')`, `processingTime (ms)`, `framesAnalyzed`, `model`, `device`, `completedAt (ISO)`.

### Storage schema

| Key | Store | Shape | Writers → Readers |
|---|---|---|---|
| `ds_user` | local | `{name, email, loggedInAt}` | login → guards, greeting, avatar |
| `ds_scan` | session | scan object (above) | upload, processing → processing, result, report |
| `ds_history` | local | scan[] newest-first, cap 50 | processing, settings(clear) → dashboard, report, settings |
| `ds_settings` | local | `{frameRate, threshold, reducedMotion, autoDelete}` | settings → report, utils(apply) |

### Event handling & DOM manipulation

- Global concerns use **event delegation** on `document` (modals, sidebar) so injected content needs no re-binding.
- Page controllers bind directly to cached elements (`cacheEls()` pattern in upload.js; `ui` map in processing.js).
- Injection policy: user-controlled strings (file names) go through `escapeHtml()` before `innerHTML`, or use `textContent`/`createTextNode` (processing console, report fields). Engine-controlled constants may use template `innerHTML`.
- After any injection containing `data-lucide`, `DS.icons()` is re-invoked.

| Site | Rules |
|---|---|
| Login | email regex `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`; password ≥ 4 chars; per-field `.invalid` + first-error toast |

## 9. User Journey

**Splash → Login.** First visit: no `ds_user`, so after the 2.4 s brand moment (skippable) the user lands on login. Returning users skip login entirely — splash routes straight to the dashboard.

**Login → Dashboard.** Any syntactically valid credentials (or guest) create `ds_user`. The 700 ms simulated latency + in-button spinner communicate "real auth" for demos. Dashboard greets by derived first name, shows zeroed stats and an empty-state table on first run.

**Dashboard → Upload.** Via sidebar, shortcut cards, or "New scan". The image and video pages are the same machine with different configs; the video page adds the URL card.

**Upload → Processing.** A valid file produces a preview + a ≤640 px JPEG thumbnail (`previewDataUrl`) that survives navigation; a ~900 ms "preparing" bar gates the Start button. Start writes the scan to `ds_scan` and navigates. Nothing heavy crosses pages — only the small scan object.

**Processing.** The engine (simulated: 5.6 s image / 8.2 s video) streams progress/ETA/stages/logs into the UI. The stage list is generated from the engine's own pipeline definition. On completion the merged scan is persisted (`ds_scan` + `ds_history`), the scanner flips to a green check, and after 900 ms the user is forwarded to the result.

**Result.** The confidence ring sweeps to the score (green for real, red for deepfake), with verdict badge, risk chip, explanation, metrics (processing time, frames analyzed, device), preview, and model card. The report links carry `?id=<scanId>`.

**Report.** Resolves its scan by id → session → latest, renders the document (verdict strip, file/detection/analysis sections, generated summary, disclaimer), and "Download PDF" prints with a swapped document title so the browser suggests `DeepShield-Report-<id>.pdf`. Print CSS produces a clean white A4 document.

Subsequent visits: dashboard stats/table populate from `ds_history`; each row deep-links to its archived report.

## 12. Performance

- **No framework, no build step.** First-party JS is ~12 small files; the largest cost is the icon library. Everything is cacheable static files.
- **Script loading:** every script uses `defer` — HTML parsing is never blocked; execution order is preserved.
- **Lazy loading:** not needed at current scale (no image galleries, one page's assets ≈ 600 KB dominated by the shared, cached Lucide file). The deliberate "lazy" behaviors are: preview thumbnails downscaled on canvas to ≤640 px JPEG q0.7 **before** storage (keeps `ds_scan` small and pages fast), history capped at 50 entries, console log capped at 80 lines, dashboard table capped at 6 rows.
- **CSS optimization:** tokens prevent duplicate values; components are shared rather than re-declared; animations use only `transform`/`opacity` (compositor-friendly) except width-based progress bars (intentional, tiny elements); the ambient glow is a single fixed pseudo-element, not per-card effects.
- **JS optimization:** event delegation instead of per-element listeners for global widgets; DOM lookups cached per page; rAF used for count-ups; intervals are cleared defensively (`runProgress`, `resetState`); object URLs revoked and video decoders released on reset.
- **CPU-friendliness:** the reduced-motion setting collapses all animation to ~0 ms — the documented escape hatch for the i3 target if animations ever feel heavy.
- Known payload trade-off: full Lucide is convenient; §19 documents the tree-shaken-sprite alternative.

## 13. Responsiveness

**Breakpoints** (consistent everywhere): **1024 px** and **640 px**, via `max-width` queries — desktop-first overrides.

| Range | Strategy |
|---|---|
| > 1024 px (desktop) | Full shell: fixed 264 px sidebar, multi-column grids (dashboard 2fr/1fr, result 1fr/1.4fr, about 3-up/4-up), content centered at 1200 px |
| 641–1024 px (tablet) | Sidebar becomes off-canvas (translateX −100 %), hamburger appears in navbar, scrim overlay when open (`body.sidebar-open`); all multi-column page grids collapse to one column (result reorders verdict above media via `order: -1`); stat grid 4→2; upload preview stacks |
| ≤ 640 px (mobile) | Paddings tighten (`--s-4`→`--s-2/3`); stat grid →1; metrics →1; action buttons go full-width/flex-1; URL form stacks vertically; settings rows become label-above-control columns; processing % 34→28 px, console 200→170 px; report doc padding shrinks and the verdict strip stacks |

Fluidity between breakpoints comes from `clamp()` headings, `%`/`fr` layouts, `minmax(0, …)` + `min-width: 0` (text truncation instead of overflow), and `.table-wrap` horizontal scrolling. No fixed widths exceed 360 px without a `max-width` guard.

## 14. Accessibility

- **Semantics:** landmarks on every page (`aside[aria-label]`, `header`, `main`, `footer`, `nav`); one `h1` per page with sane heading descent; `dl/dt/dd` for spec sheets; `role="list"` where `list-style: none` would strip list semantics.
- **Labels:** every input has a bound `<label for>` (or `aria-label` for the URL field); all icon-only buttons carry `aria-label` (+ dynamic flip on the password toggle); decorative SVGs/rings/avatars are `aria-hidden="true"`; preview images have meaningful `alt`.
- **Live regions:** toast container `aria-live="polite"`; processing console `role="log"`; splash loader `role="status"`; confidence ring `role="img"` with a spoken `Confidence N%` label.
- **Dialogs:** `role="dialog" aria-modal="true" aria-labelledby`, Esc + scrim close, focus moved to the first focusable on open.
- **Keyboard:** drop zone is `role="button" tabindex="0"` with Enter/Space activation; switches are native checkboxes; visible `:focus-visible` outline globally; hidden file inputs removed from tab order.
- **Motion:** triple-layered reduced-motion (OS media query, in-app persisted toggle stamped on `<html>`, JS checks before rAF animations).
- **Contrast:** secondary text `#94A3B8` on `#101827` ≈ 7:1; brightened badge text tints (`#4ADE80`/`#F87171`) exist specifically to keep tinted chips ≥ 4.5:1.
- **Known gaps** (also in §18): validation errors are not linked via `aria-describedby`/`aria-invalid`; modals don't trap Tab focus; `aria-current="page"` is not set on the active nav link.

## 15. Code Quality & Conventions

- **Naming:** kebab-case CSS classes with component prefixes (`stat-*`, `nav-*`, `doc-*`, `proc-*`); page CSS prefixes match the page (`splash-*`, `auth-*`, `result-*`); storage keys `ds_*`; one JS global (`DS`), PascalCase none (no classes), camelCase functions; element ids are page-scoped kebab-case (`proc-pct`, `f-name`).
- **Folder convention:** *foundation* (shared, 7 files) vs *pages* (one HTML + CSS + JS triplet per page; upload pages intentionally share one triplet). Nothing else.
- **Coding style:** section-banner comments in every file; page controllers gate on `DOMContentLoaded` and (app pages) `DS.auth.guard()` first; stateful controllers (upload/processing) use IIFE + `'use strict'`; small single-purpose functions (`validateFile`, `markStage`, `resolveScan`); no dead abstractions.
- **Architecture decisions worth knowing:**
  1. **Exemplar shell over templating** — accepted duplication of sidebar/navbar markup across 8 files in exchange for zero build tooling. The mitigation plan (Jinja partials) is §16/§19.
  2. **Engine-shaped mock** — the simulation implements the *real* interface (`analyze(scan, hooks) → Promise<result>`), so backend integration is a transport swap, not a refactor.
  3. **Stage labels pulled from the engine** (`DS.api._stages`) instead of duplicated in markup — one source of truth for the pipeline.
  4. **Deterministic mock verdicts** (filename hash + keyword steering) — demos are reproducible; "fake.jpg" always flags.
  5. **Session vs local split** — in-flight scan is tab-scoped (`sessionStorage`); durable artifacts (user, history, settings) are `localStorage`.

## 18. Weaknesses (honest)

1. **Everything trust-side is client-side.** Auth is a localStorage stub — any visitor can mint `ds_user`. Guards are UX, not security. Fine for a demo; must not be presented as access control.
2. **The engine is simulated.** Verdicts are filename-seeded theater; confidence/risk numbers carry no meaning until the model lands. The "Simulated (demo)" badge in Settings is the only in-UI disclosure — result/report pages don't disclose it.
3. **Shell duplication.** The sidebar/navbar/footer markup exists in 8 files. Any nav change is an 8-file edit (or a regeneration against the exemplar). Accepted trade-off for zero tooling, but it *will* drift under manual maintenance.
4. **`MODEL` metadata duplicated in markup.** The navbar badge (4 pages), the About model card (6 values), and the Settings system card (3 values) hardcode strings that also live in `DS.api.MODEL`.
5. **Login has no failure branch.** The submit button's label is destroyed and buttons stay disabled if navigation were ever to fail; nothing restores the form.
6. **Modals don't trap focus**, validation errors aren't programmatically associated (`aria-invalid`/`aria-describedby`), and the active nav link lacks `aria-current`. Screen-reader experience is good-not-great.
7. **Tab-scoped flow state.** `ds_scan` lives in sessionStorage: opening `result.html` in a new tab shows the dashboard redirect, not the result. By design, but surprising.
8. **Storage quota partially mitigated.** History entries drop their `previewDataUrl` thumbnail when the "Auto-delete uploads" setting is ON (the default) — this both honors the privacy toggle and keeps `ds_history` far from the ~5 MB quota. With the toggle OFF, thumbnails persist and heavy use can still hit the silent-write-failure path in `DS.store`.
9. **Guard flicker.** Unauthenticated hits of app pages paint one frame before `location.replace` — cosmetic, inherent to client-side guards.
10. **Full Lucide vendored (415 KB).** Cached after first load, but 10× larger than the ~30 icons actually used.
11. **No automated tests or linting.** Correctness currently rests on the multi-agent review pass and manual QA.
12. **Simulated system metrics.** Dashboard CPU/RAM bars are a random walk — pure demo garnish; must be wired to real telemetry or removed for production.
13. *(Review outcome, 2026-08-07):* a 3-lens automated review (shell consistency, functional wiring, quality/a11y/responsive) produced 15 findings — 4 major, 11 minor — and **all 15 were fixed**: the `[hidden]`-vs-`.empty-state` display bug (global `[hidden]` rule in `base.css`), auto-delete honored when persisting history, the in-app reduced-motion toggle now stops infinite animations (`animation-iteration-count`), closed modals and the off-canvas sidebar are removed from the tab order via `visibility`, the processing-page cancel race is guarded, processing gained its `h1`, dashboard's mock metrics respect reduced motion, `escapeHtml`/`truncate` were promoted to `DS.util`, the navbar badge no longer forces 360 px overflow, and the upload drop zone's nested-button ARIA violation was removed.
